# scripts/

Developer tooling. Node 18+ required (native `fetch`, top-level `await`).

## seed-kanban.mjs

Seeds a GitHub ProjectV2 kanban with **draft cards** from a JSON manifest.
No repo issues are created — only in-project draft items. Safe to re-run
(idempotent, dedupes by final title).

### One-time setup

1. Create a Personal Access Token
   - Classic: https://github.com/settings/tokens (scopes: `project`)
   - Fine-grained: https://github.com/settings/tokens?type=beta
     → Repository access: the repo that hosts the project (or "All repositories")
     → Permissions: **Projects: Read and write**
2. Find your project number — it's the integer at the end of the URL:
   `https://github.com/users/<you>/projects/3` → `3`
3. Make sure the project has a **Status** single-select field (default for
   new boards). Option names can be anything; the script matches them
   case-insensitively, ignoring emoji/punctuation.

### Running

```bash
# Windows cmd
cd far-study-app
set GITHUB_TOKEN=ghp_xxx
set PROJECT_OWNER=Van-growth
set PROJECT_NUMBER=3
node scripts/seed-kanban.mjs
```

```bash
# PowerShell
$env:GITHUB_TOKEN = "ghp_xxx"
$env:PROJECT_OWNER = "Van-growth"
$env:PROJECT_NUMBER = "3"
node scripts/seed-kanban.mjs
```

```bash
# bash / zsh / Git Bash
export GITHUB_TOKEN=ghp_xxx
export PROJECT_OWNER=Van-growth
export PROJECT_NUMBER=3
node scripts/seed-kanban.mjs
```

### Flags

```bash
# Preview without touching GitHub — highly recommended on first run
node scripts/seed-kanban.mjs --dry-run

# Use a different manifest file
node scripts/seed-kanban.mjs --cards scripts/sprints/2026-04-13.json
```

### Daily workflow

1. Edit `scripts/kanban-cards.json` (or copy it to a dated file).
2. Update `"date"` and rewrite `"cards"` for today's work.
3. `node scripts/seed-kanban.mjs --dry-run` → verify nothing looks wrong.
4. `node scripts/seed-kanban.mjs` → writes the draft cards.

Cards already on the board (matched by `[label] title`) are skipped, so
you can re-run mid-day to add new ones without creating duplicates.

### Manifest schema

```jsonc
{
  "date": "2026-04-12",        // optional — falls back to today
  "cards": [
    {
      "title":  "rolling buffer + 온디맨드 문제 생성",
      "label":  "feat",        // free-form. feat / fix / refactor / docs ...
      "status": "Done"         // must match a Status option on the project
    },
    {
      "title":  "학습 분석 API 무한 호출 버그",
      "label":  "fix",
      "status": "In Progress"
    }
  ]
}
```

### What the script writes to GitHub

Each card becomes a draft item with:

- **Title**: `[<label>] <title>` — e.g. `[feat] rolling buffer + 온디맨드 문제 생성`
- **Body**: `Date: <date>\nLabel: <label>\n\n_Generated by scripts/seed-kanban.mjs_`
- **Status field**: matched single-select option

Draft issues don't support repo labels directly, so the label is encoded
in the title prefix and the body.

### Troubleshooting

- `Project #N not found under "..."` — the script tried both user and org
  namespaces. Verify `PROJECT_OWNER` is the correct user/org login and
  `PROJECT_NUMBER` matches the URL.
- `Project has no "Status" field` — your board was created without a
  default Status column. Add one in the Projects UI (`+ Add field` →
  `Single select` → name it `Status`).
- `Unknown status "Done"` — the Status option doesn't exist on the board.
  Script lists available options in the error message.
- `HTTP 401` — PAT is invalid or missing `project` scope.
- `secondary rate limit` — the script already paces requests at ~150ms;
  if you're seeding huge batches, split the manifest.
